# Enterprise Incident Response & Automated Investigation Guide

This document details the architecture, data models, investigation capabilities, response automation, and incident playbooks implemented in the Enterprise Attack Detection & Response Lab.

---

## 1. Architecture Overview

The Incident Response and Investigation subsystem transforms raw security alerts generated by detection rules into structured, auditable security incidents and orchestrates end-to-end incident handling across the NIST SP 800-61 / SANS incident response lifecycle:

```
Detection Alert
       ↓
Incident Creation & Normalization
       ↓
Triage & Scope Assessment
       ↓
Automated Multi-Source Investigation & Timeline Correlation
(Authentication + Process Lineage + Network Flows + File Systems + Threat Intel)
       ↓
Automated & Safe Containment (User Disabling, Endpoint Isolation, IOC Blocking)
       ↓
Eradication & Remediation (Process Termination, Session Purge, Backup Restoration)
       ↓
Recovery & System Verification
       ↓
Root Cause Analysis & Lessons Learned (Incident Report Generation)
```

---

## 2. Incident Domain Model

Incidents are structured domain entities tracking the full operational state and forensic context of a security incident:

```python
class Incident(BaseModel):
    incident_id: str                      # Unique identifier (e.g. INC-A1B2C3D4)
    timestamp: datetime                   # Incident creation timestamp (UTC)
    severity: IncidentSeverity            # INFORMATIONAL, LOW, MEDIUM, HIGH, CRITICAL
    status: IncidentStatus                # NEW, TRIAGED, INVESTIGATING, CONTAINED, ERADICATED, RECOVERED, CLOSED
    title: str                            # Human-readable incident summary
    description: str                      # Detailed technical description
    affected_assets: List[str]            # Hostnames, server nodes, IP addresses
    affected_users: List[str]             # User accounts, service principals
    indicators: List[Indicator]           # Extracted IOCs (IP, domain, hash, user, process)
    detection_source: List[str]           # Originating detection rule IDs and alert IDs
    mitre_attack: List[MitreAttackInfo]   # Associated ATT&CK tactics, techniques, and subtechniques
    timeline: List[TimelineEntry]         # Chronological event sequence with key event flags
    analyst_actions: List[AnalystAction]  # Log of actions executed by SOAR or analysts
    containment_status: ContainmentStatus # NOT_CONTAINED, IN_PROGRESS, CONTAINED
    remediation_status: RemediationStatus # NOT_REMEDIATED, IN_PROGRESS, REMEDIATED
    recovery_status: RecoveryStatus       # PENDING, IN_PROGRESS, RECOVERED, VERIFIED
    evidence_references: List[EvidenceItem] # Forensic log events, memory dumps, pcaps
    final_disposition: IncidentDisposition# TRUE_POSITIVE_MALICIOUS, FALSE_POSITIVE, etc.
    root_cause_analysis: Optional[RootCauseAnalysis]
    lessons_learned: Optional[LessonsLearned]
```

## 3. Investigation & Multi-Source Correlation Engine

The `InvestigationEngine` provides automated investigation capabilities that correlate events across disparate telemetry datasets:

1. **Authentication Telemetry**: Active Directory Kerberos TGS/TGT requests, Windows Event IDs 4624/4625, Linux SSH authentication logs, sudo escalations.
2. **Process Execution Telemetry**: Process creations, command-line arguments, parent-child process relationships, suspicious utility invocations (`procdump`, `shred`, `mimikatz`, `sc.exe`, `powershell.exe`).
3. **Network Telemetry**: Inbound/outbound network flows, cross-subnet pivots (e.g., DMZ to internal database/controller), C2 beaconing.
4. **File & System Telemetry**: File access, modification, shredding, and registry changes.
5. **Threat Intelligence Correlation**: Real-time evaluation against internal threat intelligence databases for known adversary C2 IPs, domains, and malicious hashes.
6. **Automated Timeline Construction**: Aggregates all correlated events into a sorted, categorized timeline with key event markers and MITRE technique tags.
7. **Forensic Metadata Collector**: Captures process tree snapshots, active network sockets, logged-in sessions, and system integrity status.

## 4. Response Automation & Safety Guardrails

All response actions operate strictly under defined safety boundaries to prevent unintended disruption:

### Safety Guardrails
- **Lab Boundary Enforcement**: All targets must reside within approved lab subnets (`172.28.0.0/16`, `127.0.0.1`, `*.corp.enterprise.local`).
- **Core Infrastructure Protection**: Domain Controller and SIEM collector endpoints cannot be completely isolated without explicit operator override (`force_critical=True`).
- **Protected System Accounts**: Administrative roots (`root`, `krbtgt`) and core init daemons (`PID 1`, `systemd`) cannot be terminated or disabled by automated playbooks.
- **Idempotency Guarantees**: Applying an already-active containment state returns `ALREADY_APPLIED` without error or redundant modification.
- **Rollback Capabilities**: Reversible actions (`disable_user`, `isolate_endpoint`, `block_ioc`) record inverse rollback parameters to allow instant restoration.

### Automated Actions
- `disable_user(username)` / `enable_user(username)`: Toggles user account state in Active Directory and Linux services.
- `isolate_endpoint(hostname)` / `unisolate_endpoint(hostname)`: Applies network isolation dropping all non-SOC management traffic.
- `block_ioc(type, value)` / `unblock_ioc(value)`: Blocks malicious IP addresses at perimeter firewalls or sinkholes C2 domains.
- `terminate_process(hostname, pid, process_name)`: Sends SIGKILL (9) to malicious processes.
- `collect_forensics(hostname)`: Collects forensic artifact paths, process trees, and hash fingerprints.
- `revoke_user_sessions(username)`: Purges Kerberos service tickets and terminates active sessions.
- `restore_backup(hostname, file_path)`: Restores corrupted or shredded critical files from golden baselines.

## 6. Incident Scenarios & Playbooks

The framework provides automated playbooks for core enterprise incident categories:

### 1. Credential Compromise Playbook (`CredentialCompromisePlaybook`)
- **Triggers**: Brute force password guessing, Kerberoasting (weak RC4 TGS requests), OS credential dumping (`/etc/shadow`, LSASS).
- **Triage**: Assesses targeted user account, source IP, failure rates.
- **Investigation**: Correlates authentication logs, discovers subsequent login attempts.
- **Containment**: Disables compromised user, purges Kerberos tickets, blocks attacker IP.
- **Remediation**: Rotates credentials to AES-256, audits SPN registrations.
- **Recovery**: Re-enables verified account, validates normal authentication.

### 2. Lateral Movement Playbook (`LateralMovementPlaybook`)
- **Triggers**: Cross-subnet SSH connections from DMZ web tier, remote PsExec (`sc.exe`), WinRM PowerShell sessions.
- **Triage**: Identifies pivot source and target destination servers.
- **Investigation**: Traces network pivot path, maps executed remote commands.
- **Containment**: Isolates compromised DMZ jump host, terminates unauthorized remote processes.
- **Remediation**: Collects volatile memory and log forensics, cleans persistence.
- **Recovery**: Re-validates network firewall rules, restores host connectivity.

### 3. Malware & Ransomware Impact Playbook (`MalwareRansomwarePlaybook`)
- **Triggers**: Destructive log wiping (`shred -u -z`), critical monitoring service stops (`systemctl stop auditd`), C2 beaconing.
- **Triage**: Identifies affected host and targeted file system paths.
- **Investigation**: Maps process tree, identifies wiper parent process and C2 channels.
- **Containment**: Immediately isolates infected endpoint, terminates wiper PID, blocks C2 IPs.
- **Remediation**: Restores shredded audit logs from immutable baseline backup, restarts security services.
- **Recovery**: Verifies file system integrity, restores network access.

## 7. CLI Commands & Usage

```bash
# View active security incidents
python3 cli.py incidents

# View detailed incident report by ID
python3 cli.py incidents --id INC-A1B2C3D4

# Run automated attack simulation and investigation engine
python3 cli.py investigate --scenario SCN-CRED-004

# Run end-to-end Incident Response Playbook
python3 cli.py respond --playbook credential
python3 cli.py respond --playbook lateral
python3 cli.py respond --playbook malware

# View response action audit trail
python3 cli.py audit --limit 50
```
